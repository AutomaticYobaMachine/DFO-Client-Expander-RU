# Автообновление установщика — черновик 1.19.0

Эта функция подготовлена локально. Публикация релиза и загрузка изменений в
GitHub в рамках этой работы не выполняются. Ссылка «Скачать» в основном README
пока ведёт на опубликованную 1.18.0, в которой автообновления ещё нет.

## Поведение

При обычном запуске установщик в фоне проверяет последний стабильный релиз
`AutomaticYobaMachine/DFO-Client-Expander-RU` через GitHub Releases API.
Черновики, предварительные, равные и более старые версии пропускаются.
Версии сравниваются по числовым компонентам: 1.20 новее 1.9.

Новый Windows x64 EXE скачивается вместе с его `.exe.sha256`. Проверяются
репозиторий, имя файла, ограниченный размер, полнота загрузки и SHA-256.
Если GitHub предоставил digest в метаданных, он тоже должен совпасть.
Перед заменой выполняется короткий запуск проверенного EXE в служебном
режиме: он подтверждает продукт, версию и протокол обновления. Неверный,
повреждённый или несовместимый файл не устанавливается.

Окно остаётся доступным во время проверки и загрузки. Перезапуск откладывается
во время записи клавиши, установки/удаления расширения, диалога выбора файла,
перетаскивания окна и недавнего пользовательского ввода. Если открыты другие
окна установщика, автоматические действия ждут их закрытия. Незавершённый
выбор компонентов и клавиш переносится в новое окно и не применяется молча.
Если установщик был на заднем плане, новое окно показывается без перехвата
фокуса у игры или другой программы.

Уже установленное старое расширение обновляется автоматически при закрытой
игре, если нет неприменённого выбора. Отсутствующее расширение самостоятельно
не устанавливается; более новая версия в клиенте не понижается. Состояние
`enabled:false` сохраняется. Пока игра открыта, проверяется только список
процессов; свежий статус и проверка самого патчера подтверждают доступность
перед записью `app.asar`. Игра принудительно не завершается.

Проверка выполняется при запуске установщика. Фоновой службы, задания
планировщика или изменения автозагрузки нет. Имя переносимого EXE сохраняется,
чтобы не сломать существующий ярлык; актуальная версия показана в окне.
Первую версию с автообновлением нужно скачать вручную один раз.

## Замена и откат

Кеш загрузок находится в `%LOCALAPPDATA%\DFO-Client-Expander-RU\updates`.
Это отдельные служебные данные; настройки, фильтры и привязки игры остаются
в прежнем профиле `%APPDATA%\DFO Online`.

Windows не разрешает перезаписать запущенный EXE. Проверенная новая программа
сначала запускается как помощник обновления. Он проверяет родительский процесс
и неизменность файлов, готовит копию рядом с исходным EXE и подтверждает готовность.
Старая программа завершает работу, затем `ReplaceFileW` атомарно заменяет её
с резервной копией на том же диске. Это работает и при размещении программы
на другом диске относительно LocalAppData. Права автоматически не повышаются.

Новая программа подтверждает создание рабочего окна после распаковки компонентов.
До подтверждения помощника запись в игровой архив заблокирована. При ошибке
запуска или отсутствии подтверждения останавливается только созданный новый
процесс установщика, возвращается резервный EXE и запускается прежняя версия
с сохранённым состоянием. Повторная попытка в этом запуске отключена.
Ошибки сети, ограничение GitHub API и повреждённая загрузка оставляют текущий
EXE на месте. Недоступность каталога программы также не удаляет старую версию.

Для обновлений используются только HTTPS GitHub и его файловые CDN. Токен
GitHub не нужен и в установщик не встраивается. SHA-256 подтверждает целостность
загрузки из доверенного репозитория; это не цифровая подпись издателя.

## Проверка

Общие Go-тесты используют локальный транспорт вместо Интернета: новые/старые
версии, адреса и перенаправления, неправильные суммы, обрыв, ограничение API,
несовместимая программа, отмена, подготовка на том же диске и сохранение настроек.

```sh
cd src/gui
go test -race ./...
```

Полный Win32-стенд запускается из корня с теми же Go/Wine/Xvfb и
`DFO_WINDOWS_NODE`, что и `tools/test-installer-ui.py`:

```sh
python3 tools/test-updater-ui.py
```

Он собирает локальную будущую версию 1.20.0 и проверяет настоящий Windows EXE
под Wine: загрузку, служебный запуск, помощник, замену и видимость нового окна,
перенос несохранённых галочек и двух NumPad-привязок, автоматическое обновление
расширения только после закрытия игры и откат при повреждении встроенных
компонентов. Сохранность ASAR, настроек и кеша проверяется по содержимому.
Отдельно воспроизводится кратковременная эксклюзивная блокировка файла
подтверждения запуска. В тестовой копии будущего патчера `gameRunning()`
намеренно возвращает false: нативная проверка процессов всё равно должна
защитить открытый клиент. Этот подменённый патчер в дистрибутив не попадает.
Метаданные и файлы релиза выдаёт только локальный тестовый транспорт; внешних
загрузок или публикации нет. Проверка под Wine не заменяет прогон на Windows.

В этой среде также пройдены Go-тесты с `-race` и `go vet`, прежний Win32-стенд
ручной установки, 56 тестов Node включая упаковку. Ещё 56 проверок игровых
исходников пропущены без внешних ассетов оригинала; изменение установщика
не является новой проверкой совместимости игровых хуков.

Прежний Win32-стенд запускает установщик с `--no-self-update`, чтобы проверка
клавиш и ручной установки оставалась воспроизводимой. Этот флаг также отключает
автоматическое применение расширения. Явные CLI `--auto-install` и
`--auto-uninstall` выполняют запрошенную операцию без сетевого самообновления.

Журнал сообщает этапы и причину отказа. Отключать защиту Windows или менять
сетевые настройки компьютера для работы функции не требуется.
