База: родительский проект `Lattymoy/daggerfall-js-source`, коммит
`31e713a21a5a3c1834a27f7f18dc8d9880ddd108`, релиз `app-v0.1.14487`.
Перед реализацией повторно проверены текущий HEAD, прежние тесты переноса и
браузерный сценарий окна. Исходники оригинала не изменялись.

## Два независимых набора правил

Лутфильтр задаёт видимость ссылок в детекторе. Белый список показывает предмет
по **любому** отмеченному совпадению; чёрный список скрывает по любому совпадению.
AND между группами нет. Пустой белый список пуст, пустой чёрный показывает всё.

Автолут запускается однократно по назначенной кнопке лута (по умолчанию J), до создания окна. Совпадение любого его
тега **или** конкретного предмета разрешает попытку подбора. Фильтр отображения,
нативный поиск, категория, редкость и материал окна на эту попытку не влияют.
По умолчанию автолут выключен; включённый автолут без правил ничего не берёт.
Успешно подобранное не попадает в список. Если взято всё, окно не монтируется;
повторное J без лута открывает пустое окно для настройки.

Видимость вычисляется над временным списком ссылок. Полный список ссылок остаётся
доступен механизму автолута, но не является дополнительным контейнером.
Ни фильтрация, ни сохранение/загрузка пресета не создают и не двигают вещи.

## Теги и конкретные предметы

`loot-tags-transform.cjs` предоставляет доступ к текущим таблицам и функциям
оригинала без копирования его классификационной логики:

- страницы инвентаря и материалы — `packPages.js`, `storeFilter.js`;
- все игровые группы и виды предметов — `GROUP_TEMPLATE_INDICES`,
  `templateByIndex` и зарегистрированные custom templates из `itemTemplates.js`;
- наземные типы — `PI_CATEGORIES` и `itemCategory` из `physicalItems.js`;
- все уровни редкости — `RARITY_ORDER`, `rarityOf`;
- опознание — `itemIsIdentified`, привязка — `isBound`;
- аффиксы и их параметры — `AFFIX_KINDS` из `lootRarity.js`;
- свойства записей: квестовые, зачарованные, артефакты, опознанные/неопознанные,
  краденые, привязанные, защищённые от удаления, хлам, сломанные, возвышенные,
  проклятые, гнёзда, отпечаток, усиление, заточка, мастерская работа,
  фамильные вещи и отравленные предметы.

Каталог охватывает определения игры, а не только текущие находки. Поиск и выбор
группы ограничивают показ галочек, не удаляя остальные выбранные теги.
Материал не раскрывается там, где его скрывает карточка игры; аффиксы
неопознанной вещи также не раскрываются через фильтр.

Автолут умеет выбирать общий вид (`group + templateIndex`) из каталога игры,
Для custom template без объявленной группы используется его глобально уникальный
индекс, без угадывания группы. Можно выбрать и разновидность из вещей рядом: отдельную книгу, рецепт зелья, материал,
названную/легендарную вещь, аффиксы и т. п. ID правила разновидности не зависит
от UID, количества и износа, поэтому правило применимо к следующему такому же
предмету. Сила числового ролла аффикса в этот ID не входит. Это ID для сравнения,
а не сериализованная сущность, которую можно загрузить в инвентарь.

## Интерфейс

В существующем окне добавлены «Лутфильтр» и «Автолут». Диалог фильтра содержит
два взаимоисключающих режима: активный золотой, неактивный серый. Галочки тегов
расположены в **две колонки** с вертикальной прокруткой; поиск и группы помогают
работать с полным каталогом. Внизу — «Сохранить», «Загрузить», «Закрыть».

«Сохранить» открывает запрос имени с кнопками «Сохранить»/«Отмена».
«Загрузить» открывает список пресетов с кнопками «Загрузить»/«Отмена».
Выбор строки без подтверждения не применяет пресет. Esc закрывает только
верхний диалог. J в полях ввода не запускает подбор и не открывает другое окно.

Расширенный интерфейс получает кнопки в собственную шапку без повторного
монтажа overlay. В классическом интерфейсе доступна отдельная компактная панель
кнопок у окна; DOM-диалоги настроек общие. Закрытие/перерисовка не запускают
автолут. Если во время асинхронной загрузки настроек появилась другая панель
или сменился режим игры, отложенное нажатие отменяется.

## Кеш и экспорт

Настройки живут в `loot` существующего `dfo-mod-cache.json`:

- `filter`: режим и ID тегов отображения;
- `autoLoot`: включение, ID тегов и конкретных предметов;
- `presets`: именованные фильтры отображения;
- `revision`: версия для обнаружения конфликтующих изменений.

`loot-store.cjs` записывает этот раздел атомарно, сохраняя данные города.
Замена кеша картой сохраняет актуальный раздел `loot`, даже если она отправляет
старую копию или вообще не знает о таком разделе. Быстрые изменения галочек
объединяются перед записью, не создавая очередь из десятков больших перезаписей.
Повреждённый кеш не перезаписывается молча; ошибку сохранения получает интерфейс.
При отказе записи клиент перечитывает подтверждённое состояние и синхронизирует
галочки, режим и правила предметов; ошибка видна и после закрытия диалога.
Более новое изменение в очереди не откатывается из-за ошибки предыдущего.
Конфликт `revision` проверяется и для пресетов. После обновления списка пресетов
родительский диалог синхронизируется даже при отмене выбора. Повторный Enter
не запускает несколько сохранений. При отказе кеша созданный файл откатывается.

Сохранённый пресет имеет UUID и читаемое имя. Его JSON записывается в
`%APPDATA%\DFO Online\dfo-mod-loot-presets\<UUID>.json`; копия выгружается
через браузерный механизм скачивания под выбранным именем. Имя не используется
как путь на диске. Одинаковые имена не перезаписывают существующий пресет.
В пресет входят **только режим и теги фильтра**: загрузка не меняет автолут.

## Сохранность предметов

Подбор остаётся в `dfo_loot.js`: актуальный источник, радиус 15 м, предел высоты
1,25 м и прямой доступ по живому коллайдеру проверяются
повторно, затем используются штатные `planTake` и `applyTransfer` непосредственно
из живого списка источника. Вес проверяется заново после каждого взятия;
допустимые частичные стопки разделяет игра. Сетевые протоколы тела/комнаты,
подтверждения и отклонения выдачи сохранены. Нет фонового сканирования с подбором,
нового мирового контейнера, локальной генерации чужого дропа или повторного
переноса из массива интерфейса.

«Забрать все» использует текущий отображаемый список с фильтрами и поиском,
перепроверяет вместимость для каждой вещи и закрывает окно только при полном
успехе и отсутствии оставшихся строк. При остатке окно остаётся; отказ по весу
отображается штатным сообщением игры. Проверки стен/дверей/этажей описаны в
[nearby-loot.md](nearby-loot.md).

Ограничения оригинала на чтение/взятие чужого тела сохраняются: радиус детектора
15 м не расширяет `CORPSE_TAKE_RANGE` (5,75 м в исследованном релизе).

## Проверки

```sh
DFO_UPSTREAM_DIR=/tmp/dfo-upstream node --test --test-isolation=none test/nearby-loot.test.cjs test/loot-filter.test.cjs test/loot-access.test.cjs
node tools/check-build.cjs /tmp/dfo-release-0.1.14487
node tools/test-nearby-loot-browser.cjs /tmp/dfo-upstream /tmp/dfo-release-0.1.14487
sh tools/build.sh
node --test --test-isolation=none test/packaging.test.cjs
```

Покрыты прежний ручной подбор, режимы по любому тегу, независимость автолута,
частичные стопки, вес, отсутствие переноса при настройке, конфликты кеша,
сохранение файлов, отмена, повторное нажатие и перезапуск. Настоящий сетевой
стенд оригинала проверяет конкурирующий ручной и автоматический подбор: вещь
остаётся у одного авторитетного держателя. Chromium использует опубликованный
интерфейс, проверяет реальный каталог тегов и длинный виртуализированный список.
Добавлены отказы записи/дубли имён/двойной submit, видимый откат всех контролов,
обновление из другого окна, Escape в select, стены/этажи и «Забрать все» с
автозакрытием и настоящим сообщением игры о перегрузе.

Проверки GUI установщика под Windows и живой игровой сессии остаются отдельными:
Linux-среда проверяет сборку и установку на временном ASAR, а не реальный клиент.
