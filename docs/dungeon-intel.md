# Карточки данжей — DFO-Client-Expander-RU 1.14.2

Основной оригинал: <https://github.com/Lattymoy/daggerfall-js-source>.
Проверенная база: `a3eb1605ea1dc391b691fe314377458a7e63e483`,
`app-v0.1.14516`, 2 ноября 2026. Оригинал обновляется часто: эта запись
подтверждает конкретную базу, а не будущие релизы.

## Поведение

Три строки на найденной метке географического данжа Overworld:

1. `[Тип - N ранг] S/M/L Собственное имя`.
2. `Обычный/Элитный данж, постоянный данж/порождённый`;
   у порождённого — оставшееся время `Исчезнет через: X ч. Yм.`, если доступен журнал.
3. `|☠☠☠|◆◆|↑↑↑↑| ★ - 2,5`: угроза красная, добыча золотая,
   рост зелёный, Слава белая. Неизвестное значение заменяется `?`.

Цвет штампа определяется преобладающей семьёй ожидаемых врагов: нежить —
светло-голубой, природные создания — голубой, даэдра — красный, орки/великаны —
зелёный; остальные и смешанные — нейтральный. Имя окрашено отдельно.
Кириллица и символы рисуются системным шрифтом; череп использует текстовое
начертание, чтобы emoji-шрифт не отменял красный цвет.

Используется штатный canvas HUD: фильтры, отведение перекрывающихся подписей,
показ на краях экрана и проверка клика получают размеры всей подписи.
Города, событийные залы, Super/Abyss, специальные PvP-залы и ненайденные `?`
сохраняют своё прежнее поведение. Нет второго слоя HTML-меток.

ЛКМ открывает одну карточку. Повторный вызов обновляет её; вкладки не создают
новый диалог. «Отправиться» вызывает исходную проверку пути и исходный маршрут,
в том числе для порождённых данжей. Принятый игрой маршрут закрывает окно;
отказ оставляет его открытым с сообщением. Уход из наружного мира, опускание
Overworld (включая выход из-за опасности) и замена игрового host закрывают
карточку. Только состояния rising/up позволяют её открыть и начать путь;
проверка выполняется при клике и внутри привязки мира, без ожидания таймера.
Esc закрывает только верхний диалог; ввод в карточке не запускает
горячие клавиши игры. Вкладки поддерживают стрелки, Home и End.

Вкладки:

| Вкладка | Содержание |
| --- | --- |
| Оценка | Персональные индексы, причины угрозы, пригодность оружия, цели посещения; открыта по умолчанию |
| Обитатели | Распределение случайных видов, уровни, усиление, уровень вызова, минимальный металл, бюджет элитных врагов |
| Добыча | Ранг, Удача, вложенные пороги редкости, предпочтительная семья и именованные легендарные вещи |
| Сила и рост | Персональный прогноз уровней/усиления/обучения, доля места и пояснение штатных формул |
| Сведения | Размер, регион/ID/координаты, срок жизни, Aurum и жилы, группа/квесты и датированные наблюдения клиента |

«Мини-гайд» в отдельном диалоге объясняет индексы и их расчёт. Сведения о
сопартийце относятся к данжу только при явном ID комнаты либо сочетании
координат, режима подземелья и имени места; одних координат недостаточно.

## Данные оригинала и ограничения

Используются функции загруженного клиента, а не скопированные устаревшие числа
из переписки. Переименования minified-переменных допустимы: привязки ищутся по
свойствам и структуре. Неузнанный хук регистрирует ошибку и сохраняет исходный код.

| Источник в родительском проекте | Что читается |
| --- | --- |
| `src/characters/encounterTableDoor.js`, `dungeonEnemies.js`, `enemy/enemyBasics.js` | Все варианты таблицы, закон выбора случайного врага, свойства и имена |
| `src/systems/skillSoftcap.js`, `heroThreat.js` | Навыки, усиление от места/персонажа, уровень вызова, вес обучения |
| `src/systems/loot/lootRarity.js` | Ранги 19 типов, семьи, пороги редкости, предпочтительные легендарные вещи |
| `src/systems/eliteFoes.js` | Детерминированный бюджет элитных врагов |
| `src/net/renown.js` | XP Славы за убийство и его предел при текущей Славе |
| `src/world/spawnedDungeons.js`, `src/net/wire.js` | Срок из записи журнала, перевод игрового времени в локальные часы с поправкой сервиса |
| `src/world/smallerDungeons.js`, `dungeon/dungeonLabel.js`, `dungeon/curatedSplice.js` | Размер по правилу построения без генерации раскладки |
| `src/scenes/dungeonIdentity.js`, `src/net/nodeLaw.js` | Полная идентичность данжа, климат, детерминированные жилы дня |
| `src/net/aurumCacheLaw.js`, интеграция `deepWaterRuntime` | Aurum и локальная отметка текущего аккаунта/недели |
| `src/scenes/travelViewMarks.js`, `world.js`, `src/ui/travel/travelViewHud.js` | Метки, штатный клик, проверка пути, HUD и hit box |
| `src/scenes/dungeonContext.js`, `src/world/actionSystem.js` | Уже доступные наблюдения посещённой сцены |

Распределение вычисляется аналитически по всем веткам нативного случайного
выбора. Несколько предлагаемых таблиц усредняются равновесно: мод не выбирает
активную таблицу и не меняет состояние другого мода. Фиксированные, водные,
квестовые враги и сохранённая серверная комната могут отличаться.

Для размера читается `builtSizeFor`; `dungeonTierLabel`/`dungeonLocationFor`
из карточки не вызываются: первая функция может через вторую перестроить
раскладку и изменить глобальный DFRandom. Подсчёт бюджета элитных врагов вызывает
нативный выбор только на четырёх изолированных записях-кандидатах с его частным
RNG. Это верхний бюджет, а не подтверждение присутствия: нужны подходящие
враги. В офлайне возможен дополнительный отсев по уровню. Игровые сущности не
создаются; фактическое число точек без чтения блоков неизвестно.

Пороги редкости показываются в процентах для одного подходящего предмета,
с переводом нативных промилле. Они вложенные, не независимые и не относятся
ко всему сундуку. Награда Aurum доступна только онлайн; отсутствие локальной
отметки не доказывает серверную доступность. Для жил неизвестна выработка.

Нет записи spawn ledger — таймер неизвестен. Это не утверждение «никто не
входил». При истёкшем сроке показывается «срок истёк»; игрок внутри может
задержать исчезновение. Клиент не запрашивает общий список игроков в данже.
Квестовая метка на координатах является подсказкой, а не доказательством
принадлежности конкретной комнате/инстансу.

## Формулы индексов мода

Это оценки для выбора цели. Они не обещают победу, определённый дроп или
количество предметов за час. Все средние взвешены по распределению врагов.
Округление индексов 1–5 ограничивается этими пределами.

- **Угроза:** `1 + 1,1 × средний_уровень / max(5, ваш_уровень) + доля_боссов
  + 0,55 × log₂(max(1, средний_HP × средний_урон)) + доля_неподходящего_металла`.
  HP/урон — множители от нативной прогрессии и Elite. Босс — нативный признак
  добычи: affinity Daedra либо уровень от 18. Особые элитные черты и тактика
  в индекс не входят. Металл — базовая проверка оружия в руках, без заклинаний.
- **Добыча:** `1 + 2,5 × ранг / 18 + доля_боссов + 0,5_за_Elite`.
  При выключенной системе редкости — 1. Персональные точные шансы находятся
  во вкладке «Добыча»; индекс не включает неизвестное число источников.
- **Рост:** `1 + 4 × clamp(средний_вес_обучения / 1,5, 0, 1)`.
  До лучшего боевого/магического навыка 100 — вес 1,5. Выше 100 используется
  нативный `challengeQuality(5 × уровень_вызова + 30, лучший_навык)`.
  Обучение магии вне боя не оценивается. Отсутствующие навыки дают `?`.
- **Слава:** `5 × средние_нативные_XP / максимальные_нативные_XP_за_убийство`,
  округление до десятых. При неизвестной Славе — `?`, офлайн — 0.
  Бонус группы и ограничения сервиса могут изменить фактическое начисление.

## Кеш и нагрузка

Сводки пишутся в `dungeons` существующего
`%APPDATA%\DFO Online\dfo-mod-cache.json`, максимум 200 новейших мест.
Обновления карты города и лута сохраняют этот раздел. Сводки содержат только
ID, время, онлайн/офлайн и нормализованные счётчики. Инвентарь, игровые
сущности и содержимое сундуков не сериализуются. Старое наблюдение не заменяет
более новое. Запись атомарная; сбой оставляет предыдущий файл и показывает
ошибку. Новая попытка после сбоя записи откладывается на 30 секунд.
Недоступный список целей лута даёт неизвестные счётчики, а не ложные нули.
Нативное исключение специальных мест применяется и при записи наблюдений.

Наблюдение текущей посещённой сцены проверяется раз в 1,5 секунды; запись
выполняется при изменениях либо раз в 30 секунд. Прогноз кешируется на секунду
по локации и данным персонажа, спрайты — до 96 вариантов. Чтение файлов
блоков, генерация противников и дополнительные запросы игровых сервисов не
выполняются. Отключение: `"dungeons": false` в `dfo-mod.json`.

## Проверка

```sh
DFO_UPSTREAM_DIR=/tmp/dfo-upstream DFO_BUILD_DIR=/tmp/dfo-release-0.1.14516 \
  node --test --test-isolation=none \
  test/nearby-loot.test.cjs test/loot-filter.test.cjs \
  test/loot-access.test.cjs test/dungeon-intel.test.cjs test/dungeon-bridge.test.cjs
node tools/check-build.cjs /tmp/dfo-release-0.1.14516
node tools/test-dungeons-browser.cjs /tmp/dfo-upstream /tmp/dfo-release-0.1.14516
node tools/test-nearby-loot-browser.cjs /tmp/dfo-upstream /tmp/dfo-release-0.1.14516
node --test test/packaging.test.cjs
```

Для браузерных сценариев нужны Playwright и Acorn из окружения родительского
проекта, системный Chromium (или `DFO_CHROMIUM`); тест привязок также использует
eslint-scope из этого окружения. `DFO_SCREENSHOT_DIR` сохраняет скриншоты
карточки/меток. Стенд использует настоящие опубликованные world/HUD, контроллер
ввода Overworld и таблицы клиента с небольшим тестовым host, без загрузки всей
игровой сцены. Клики проходят через нативные pointer-события, без отдельного
тестового обработчика click.

Проверки охватывают точное распределение противников, чистоту RNG, совпадение
размера с реальным построением, нативные единицы наград, персональные данные,
таймеры, кеш и сбои записи/чтения, скрытые места, hit box третьей строки и краёв,
вкладки/мини-гайд/Escape, единственную карточку, отказ/принятие пути и перезапуск.
Сохранены исходные проверки подтверждения пути и сброса намеченной атаки перед
открытием карточки. Проверены клавиатура и размещение окна при 720×600,
закрытие карты из-за опасности, немедленный отказ путешествия после её
закрытия, смена мира, неизвестные счётчики и исключённые специальные места.
Тест привязок исполняет фактический вставленный объект из опубликованного
bundle с нативными spawn ledger и переводом часов: проверяются живая экипировка,
Удача, поправка сервиса, отсев прежней жизни порождённого данжа и маршруты.

Исторический результат 1.12.1: 46 тестов логики/нативных функций/сетевого стенда и один тест
установки/повторной установки/удаления прошли. На ассетах 0.1.14512 и 0.1.14487
найдены все ожидаемые хуки, 372 изменённых модуля разбираются без синтаксических
ошибок; браузерный сценарий карточки прошёл на обоих релизах. 0.1.14487 проверен
дополнительно, поскольку `app/lib/hostingPin.cjs` оригинала ещё закрепляет его.
Дифференциальная проверка 12 модулей данжей не обнаружила новых неопределённых
привязок. Прежний браузерный сценарий лута, фильтров и автолута прошёл на 0.1.14512.

Для 1.14.2 прошли 57 проверок логики/нативных функций/сетевого стенда, упаковка,
Go-тесты и оба браузерных сценария на ассетах 0.1.14516. Все ожидаемые хуки
найдены, синтаксических ошибок нет. Подробности — [объединение локальных
исправлений](local-fixes-import.md).

Браузерный стенд и успешная сборка не заменяют живую сетевую сессию или запуск
установщика на Windows.
