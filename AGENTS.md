# Контекст проекта

- Этот репозиторий — неофициальное расширение пользовательского клиента
  Daggerfall Online, а не родительский проект игры.
- Основной оригинал: https://github.com/Lattymoy/daggerfall-js-source.
  Другие репозитории Lattymoy — вспомогательные источники, если они относятся
  к решаемой задаче.
- Родительский проект обновляется очень часто. Перед адаптацией хуков и перед
  заявлением о совместимости проверяйте актуальные исходники и релиз оригинала.
  Не считайте старую локальную копию или номер версии из README текущими.
- С 2 ноября 2026 README оригинала называет публичный репозиторий снимком,
  не следующим за живой игрой. Неизменный HEAD не подтверждает совместимость:
  проверяйте также фактически опубликованные ассеты и последний релиз.
- Версия игры 0.1.14487 указана в импортированном README.txt как ранее проверенная;
  она не означает, что мод проверен с последним релизом оригинала.
- Исходная база расширения: DFO Mod 1.9.0 из пользовательского архива
  dfo-mod-source(1).zip. При первоначальном импорте все 568 файлов сохранены
  без изменения содержимого; внешний каталог архива dfo-mod/ убран.
- Сохраняйте сведения об авторстве и лицензиях переводов и исходных таблиц.

# Работа с исходниками

- Код установщика находится в src/gui/ (Go, Win32); код патчера и хуков —
  в src/; данные перевода — в data/; инструменты — в tools/.
- Команда сборки из корня: sh tools/build.sh. Нужны Go 1.24+ и Python 3;
  результат предназначен для Windows amd64. Скрипт пересоздаёт dist/.
- tools/build-ru-pack.py меняет данные перевода на месте. Не запускайте его
  для обычного импорта или проверки, когда изменение перевода не требуется.
- Для проверки хуков выбранного релиза используйте tools/fetch-build.mjs
  и tools/check-build.cjs. Проверку синтаксиса и успешную сборку не выдавайте
  за проверку совместимости с текущей игрой.
- .github/workflows/build.yml собирает main и сохраняет EXE с SHA-256 только
  как артефакт Actions. Он не публикует релизы. Выпуск через release.yml и
  отправка тегов — отдельное действие по запросу пользователя.

# Единая карточка предмета (рабочая версия 1.19.4)

- По прямому решению пользователя карточка одна во всех окнах: не делить
  на компактную/подробную, не вырезать свойства при наведении или смене контекста.
  Старые item-card-proposals.* — архив; актуальный стенд — docs/item-card-stand.html,
  описание — docs/item-card-stand.md. Реализация — docs/item-cards.md,
  src/mod/item-cards-transform.cjs и src/mod/page/dfo_item_cards.js.
- Сохранить самостоятельные блоки сравнения экипировки/аффиксов/температуры,
  наборов, сигилов с ростом и ограничением славой, техники, сокетов и уникальных
  сил. По уточнению пользователя от 5 ноября карточка — незакрепляющийся тултип
  без внутренней прокрутки, раскрытия и действий. Не скрывать/обрезать свойства.
  Последний запрос требует НИКОГДА не выходить за экран: при физической нехватке
  места разрешена аварийная подгонка всей карточки. На обычном Full HD размер
  текста сохраняется; размер 600–740 px — до аварийной подгонки.
- База — Full HD 1920×1080. По последнему уточнению стенд уже и выше: обычная
  ширина 600 px, максимум 740 px, высота до 960 px с учётом доступного места.
  Всегда два столбца: слева изображение и общие сведения,
  справа надбавки, эффекты и сравнение. С 1.19.4 последние цельные блоки
  могут переходить под общие сведения слева, если это уменьшает высоту.
  Выбирать непрерывный хвост в исходном порядке, измеряя реальную высоту
  в более узком столбце. Переносить узлы, не копии; не делить/скрывать строки.
  Балансировать при подгонке ширины, содержимого и шрифтов, не при каждом
  перемещении мыши. Собственные переносы не должны запускать MutationObserver
  по кругу; цена при подгонке не пересчитывается. Проверка —
  tools/test-item-card-balance.cjs. Названия групп: «Пассивные свойства»
  и «Накладывает при попадании».
  По последнему решению пользователя
  описания пока не внедрять в карточку: внизу только ценность в правом углу, без пустого
  блока описания. Инфраструктура описаний готова — см. раздел «Описания предметов». SNAC со скриншота пользователя
  входит в примеры; не выдумывать отсутствующую на скриншоте цену/ID шаблона.
- Именованные эффекты показывать по одному на строке. Сигилы и наборы переносить
  как в обычном игровом тултипе: штатные построители с параметрами по умолчанию
  и неизменённые SIGIL_BLOCK_CSS/SET_BLOCK_CSS, без переупаковки внутренней сеткой.
  Встроенный класс compact — формат родного блока, а не второй вид нашей карточки.
  Дополнительные примеры со скриншотов: Embrace of the Grave, зачарованная одежда,
  Перчатки Сбора/Wyrd и Наголенники Руна; неизвестные цену и шаблон не угадывать.
- Стенд использует исходные построители блоков с демонстрационными данными,
  не игровой расчёт экипировки. Его проверки не подтверждают совместимость
  с живым клиентом или корректность боевых расчётов.
- Проверка стенда: tools/test-item-card-stand.cjs (Playwright/Chromium).
- Рабочая функция itemCards независима от RU/лута/данжей, включается отдельной
  галочкой EXE. Оборачивать общий infoCard расширенного интерфейса: инвентарь,
  контейнеры, торговля и ссылки. При неподдержанной сигнатуре сохранять родную карточку.
- Цена по решению пользователя — 40% от штатной базы продажи с поправками вещи,
  без личных навыков и магазина. См. docs/item-prices-audit.md. Использовать родной
  tradeCost Sell с quality 10/index 1000, делить cost на 2 и брать 40%; сохранять
  родные ограничения обратного выкупа. Делитель 7,3 и надбавка ×1,4 отменены.
  Сумму стопки округлять до ближайших 10, перед ней ~; внизу только жёлтая сумма
  и монета. Килограмм считать по неокруглённой оценке и полному весу стопки.
  Аккредитивы и настоящие золотые монеты — точный номинал без округления/~.
  Сохранённое item.value уже учитывает надбавки; не прибавлять их снова.
  Без значения допустим расчёт только по существующему шаблону, не native fallback 1.
  По уточнению пользователя неопознанные вещи тоже получают оценку, как у торговцев:
  сохранённая стоимость доступна без идентификации. Скрытые названия чар, надбавки
  и сравнения не раскрывать; отсутствующий номинал бумаги не подменять ценой шаблона.
  letterWorthGold возвращает строку: использовать её как признак аккредитива,
  а числовой номинал читать из value, не разбирать локализованный текст.
- Пользовательские шрифты лежат в src/mod/fonts с исходными байтами и notices:
  Greengoth — имена, Flexi — числа, Gabin — обычный текст, Ckazka — сигил, Ritalin — набор,
  Wolgadeutsche — имя легендарной силы. Только локальные запросы; учитывать
  позднюю загрузку шрифта в подгонке. Родной DOM сигилов/наборов не менять.
- Не декодировать отсутствующий material как Iron. У цепных материалов 256/259
  металл неизвестен; RRI Fur — мех. Соблюдать родную видимость материала.
- Контекст нативных функций создавать на уровне модуля: minifier затеняет имена
  импортов локальными строками. RU перехватывает textContent синхронно: сравнивать
  подписи/ремесленные строки после той же локализации, а не только по английским словам.
- Сигилы/наборы/техники/сравнение и интерактивные сокеты переносить исходными узлами,
  не клонировать их обработчики. Штатные действия выбранной вещи сохранять вне
  содержимого hover. Родные fitCard/fitTip не должны прятать строки нашей карточки.
- Проверки реализации: test/item-cards.test.cjs и tools/test-item-cards-browser.cjs
  с фактическими ассетами оригинала. Измерение макета не заменяет сетевую игру.
- Строгие границы относятся ко всему host, включая штатные кнопки, пояснение
  картинки, кошелёк и картотеку; учитывать visualViewport и преобразования предков.
  Простого clamp координат недостаточно, если сама карточка выше/шире экрана.
  Не возвращать глобальный MutationObserver всего HUD, фоновые таймеры и расчёты
  цены на каждом изменении размеров. Наблюдатели живут только у открытых карточек
  и отключаются при закрытии/перерисовке. Проверка — tools/audit-item-cards-browser.cjs.
- itemLine.weight уже включает stackCount: ценность/кг = сумма стопки / вес стопки.
  Номинал аккредитива округляется вниз по правилу родного letterWorthGold;
  небезопасно большие числа не показывать как точную цену.
- Заголовок редкости брать из первой родной строки после метаданных при наличии
  native data-rarity, не из списка английских/русских слов: существуют Perfect,
  Exalted, Cursed и Damned. Сохранять их точную локализованную подпись.
- Второй аргумент родного fitCard — числовая высота, не флаг invalidation.
  Повторный fit без изменений не должен переизмерять или писать тот же DOM.
  При изменившейся геометрии явный fit всё же измеряет её сразу; null/чужие
  карточки оставлять родному обработчику.
- Рамка .packdetail переопределяет типографику ul.rarity и dl.stats: проверять
  computed styles собственных полей и при наведении, и при выборе. Наши подписи
  параметров — слева, значения — справа; длинные подписи не пересекают столбцы.
  Не распространять эти переопределения на родные сигилы/наборы/сравнения.
- Расширенная матрица состояний — tools/test-item-card-states.cjs. Для настоящих
  иконок задавать DFO_ARENA2_DIR; данные ARENA2 не копировать в репозиторий/релиз.
  DFO_CARD_MOD_DIR позволяет проверять фактически встроенный payload.
- Daedric и Orcish в материале — металлы, не одноимённые языковые навыки.
  Контекстные подписи задавать в карточке по каноническому коду; не менять
  глобальный перевод навыков ради исправления материала.
- Материал находится в блоке имени между названием и основным параметром,
  уменьшенным шрифтом. Подпись песочная, значение окрашено по каноническому металлу;
  эбонит/даэдрик тёмные со светлой/красной обводкой. Цвет не должен раскрывать
  скрытый материал; недостающие данные не угадывать.
- В собственных группах свойств подписи/префиксы песочные, значения и названия
  эффектов белые, хвостовые диапазоны в скобках тёмно-серые. Для строк без двоеточия
  использовать родные локализованные itemPowers. Не менять цвет родных сравнений,
  сигилов и наборов. Фрагменты уже переведённого текста вставлять как TextNode,
  иначе глобальный RU-хук может повторно перевести их с потерей контекста.
- tools/test-item-card-trade.cjs проверяет один объект через настоящие строки
  инвентаря/Sell/SellMagic/Buy: цена одинакова независимо от магазина и навыков.
  SellMagic фильтруется родным isEnchanted, а не редкостью. Тест не продаёт вещи.
- Не искать DOM-привязки карточек в entry points Worker: там большие дубли
  урезанных таблиц. При оптимизации regex проверять границы идентификаторов
  и побайтную неизменность результата на текущем игровом JS.

# Описания предметов (подготовка, 6 ноября 2026)

- Спецификация — docs/item-text.md. Таблицы — src/mod/item-text/<en|ru>/ (CSV),
  загрузчик item-text.cjs, генератор page/dfo_item_text.js (API __dfoItemText).
  В карточке описания ещё не выводятся: подключать в нижнюю полосу у цены
  только по отдельному запросу пользователя.
- Язык описаний — по установленной русификации: русский при ru (установлена и
  включена), иначе английский. Странице отдаётся одна локаль. Установщик кладёт
  en всегда, ru — только с русификацией. Пустой/битый пакет не ломает игру.
- Описание — отдельные предложения: идентичность (легендарка, рамка «база +
  материал» или основа по templateIndex), затем по фразе на каждое модульное
  свойство в фиксированном порядке. У каждой базовой вещи в RU
  заранее проставлен род (m/f/n) или p для слов без единственного числа
  («перчатки», «сапоги»); каждое свойство в RU имеет все формы m/f/n/p.
  Английский: число s/p. Роды согласованы с ru_items.js.
- Не раскрывать скрытое: неопознанная вещь — только основа, видимый материал,
  редкость, Exalted, состояние и фраза о скрытых чарах. Опознание и видимый
  материал приходят от карточки (facts); сырой код материала не декодировать.
  Шаблон без строки основы не получает описания. Предмет не изменять.
- Числа не дублировать: фразы художественные, цифры остаются в строках свойств.
  Имена заклинаний/существ в описание не подставлять (нужно склонение перевода).
- Фрагмент — одно предложение 5–15 слов во всех формах и подстановках (тест).
- Решение пользователя (6 ноября, отменяет ранжирование с лимитом 5): описание
  всегда строится по одной очереди из 7 позиций (src/mod/item-text/rules.json):
  1) вещь + тип брони + материал / вещь + материал / вещь — проверять в этом порядке;
  2) редкость + сигил + набор / редкость + сигил / редкость + набор / редкость
  (combos/tiers.csv, названия наборов — combos/sets.csv по переводу русификации);
  3) и 4) по одному случайному из: именная сила, техника, аффиксы и чары (до 2),
  содержимое и еда (до 2), отдельная фраза о материале, рост сигила;
  5) один случайный из: техника, ремесло, камни, скрытые чары или проклятие;
  6) износ — только у надеваемого (оружие, броня, украшения, одежда);
  7) краденое (квестовое отделено: о нём говорит подсказка). Без повторов по всему
  описанию; случайный выбор устойчив (зерно из предмета), пустые позиции пропускаются.
  Окраска, привязка, призыв, памятная вещь и останки в очередь не входят.
- Подсказка игроку (решение пользователя 6 ноября) — позиция 8, у КАЖДОЙ вещи, всегда
  последняя, отдельным абзацем после одной пустой строки, белым: что делать с вещью по
  механикам игры, но тем же художественным тоном, что и описание. Краденое — отдельной
  строкой сразу под описанием, красным (category standing). Легендарки (и проклятые
  неснимаемо): не разбирать — носить, беречь для отпечатка силы или продать на рынке. Сначала состояние (квест, неопознана, проклятие, ремонт, артефакт,
  эфирная, легендарка, набор, сигил, изделие мастера, редкая, магическая, испорченная
  еда, душа), иначе подсказка основы из hints.json. Обычные оружие и броня — «в крайнем
  случае лучше, чем ничего»; вещи только на продажу — «безделушка на продажу». Что
  берут за серебро — второе предложение: материалы рынка (Предписания Двора), у персонажа
  в гильдии (facts.guild) — «Возможно, моя гильдия будет заинтересована в этом
  предмете…»; зелья, блюда и ремкомплекты — ремесленные предписания. Факты брать из
  исходников игры (станции, рецепты, предписания), не придумывать.
- Зелье — только у бутылки UselessItems1 83, душа — у ловушки душ 274/Звезды Азуры,
  яд — у оружия: potionRecipeKey (0 по умолчанию), trappedSoulType и poisonType есть у
  всех вещей. Около 2/5 фраз эффектов и материалов — от лица игрока («Вы чувствуете,
  как…», «Вы видите…»); без шуток и натянутых сравнений.
- Комбинированные фрагменты: оружие и броня — «вещь + тип брони + материал»
  (combos/gear.csv: leather/chain/plate; RRI mail/fur/brigandine, щиты тоже),
  металл подставляется из combos/metals.csv; непоказанный металл — нейтральный
  «блестящий металл», непоказанный тип брони — нейтральная основа. Пары свойств
  ремесла/чар — combos/properties.csv; сигилы и наборы объединяются только с
  редкостью в позиции 2, износ не комбинируется никогда.
- Легендарки и золочёные — уникальная фраза «{base} + легендарная сила» с формами
  рода базы (combos/legendaries.csv), только после опознания; это фрагмент
  именной силы позиций 3–4, позиция 1 у них — обычная рамка. Сигил и набор игра
  показывает и до опознания. Тип брони карточка передаёт как facts.armorType.
- Шрифт всех описаний — Flow Ext Bold (docs/fonts/item-font-description.otf), 12 px;
  описание светло-серое #c4c6ca, подсказка белая. EULA требует письменного разрешения
  только для коммерческого использования (сообщение пользователя): бесплатному моду
  распространять можно, без изменений и с FONT-NOTICES. В EXE — вместе с выводом
  описаний в карточку.

# Навигация в данже (1.17.x)

- Спецификация — docs/dungeon-navigation.md. Четыре цели и отмена находятся
  на вкладке «Сводка»; после выбора окно закрывается и рисуется линия по полу.
  Сохранять нативный вид, K/переназначение и прежнее автообновление сводки.
- Только чтение мира. Не двигать игрока/цели, не менять настройки ИИ или квестов,
  не вызывать действия дверей, claim аурума, подбор и игровую генерацию.
- Использовать собственный граф dfo_dungeon_graph.js и профили реальной геометрии.
  Не возвращать NavClient, сетку или решатель НПС. Отдельный worker принадлежит
  расширению; при его отказе тот же поиск идёт короткими порциями.
- Профили кешируются по отпечатку фактической геометрии в отдельной IndexedDB,
  максимум 256 записей. Только локальные точки/связи, без текущих сущностей,
  маршрутов и позиций экземпляров. Повреждённый профиль пересоздавать.
- Линия остаётся пространственным маршрутом: рычаги/кнопки не превращать в этапы
  и не требовать подтверждения взаимодействий. Шахты допускают лазание, спуск
  и траекторию настоящей движущейся опоры. Толстый объёмный лифт не отбрасывать
  по высоте его bounding box. Движение платформы не инвалидирует весь граф.
- Проходы проверяются по реальной геометрии: потолок, ширина, ступени и этаж.
  Опора обязательна для ходьбы; вертикальное лазание/спуск проверяются отдельно.
  Не рисовать прямую линию при отсутствии пути. Точка подхода не даёт доступа
  к цели за тонкой стеной. С 1.16.1 по запросу пользователя двери, включая
  запертые/специальные, и проходимые механизмы исключаются из расчёта и проверки
  линии. Открытие/активация остаётся игроку; физический Collider не изменять.
  Лифтовые/мостовые настилы сохранять как опору; статические рычаги/вентили в
  общем bucket исключать только в отдельном представлении геометрии навигатора.
- Использовать весь загруженный данж без фильтра разведки. Порталы брать из полного
  action graph (`automapPortals`), включая не посещённые, а не только записи карты.
  Переходы — только по направлению. Их метки подняты над
  землёй, сначала находить локальный пол. Не рисовать линию через телепортацию.
- Линия рисуется в мировом проходе ДО воды/HUD и resolve освещения, с depth test.
  У обычных party ping сохранять пунктир. При остановке/смене сцены освобождать
  GPU-ресурсы; маршрут привязан к точному ctx и сетевой комнате.
- Квесты сопоставлять по UID, включая одинаковые имена. Выбор и активный SELECT
  не пересоздавать при автоматическом обновлении. В простое не сканировать журнал,
  в проходе отрисовки не искать пути. Сущности и маршруты в кеш расширения не писать.
- С 1.19.2 см. docs/dungeon-quest-navigation.md: связывать квестовый предмет
  по UID/symbol с itemQueue живого носителя, существующим инвентарём/телом или
  напольной кучей. Получение вещи не требует KilledFoe. Не вызывать генерацию,
  AddItemQueue, update/checkTrigger, claim/takeLoot ради поиска цели.
  Использовать текущую версию ресурсов после resync, скрытые/завершённые цели
  и чужие недоступные тела исключать. HaveItem будущей награды не блокирует
  существующую цель; отдельные оставшиеся kill/injury/talk условия сохранять.
  Журнал читать только для квестовой навигации/открытого окна; навигатор
  опрашивает его максимум 4 Гц. Счётчики HUD журнал не читают.
  Порталы собирать при запросе пути, не при каждом обновлении/отрисовке линии.
- Опорные точки не соединяются по совпадению X/Z через этажи. Для лазания нужны
  стена и выход, для спуска — свободная траектория, для платформы — её настоящие
  конечные положения. Портальные эвристики не должны отбрасывать короткий путь.
- Не повторять безуспешный запрос в неизменном мире. Сравнивать координаты через
  Array.from, чтобы Float32Array и обычный Array давали одинаковый ключ.
- Луч проверки включает оба конца отрезка: точка ровно на плоскости стены
  не разрешает войти на конце одного шага и выйти через epsilon следующего.
  Проверять пояс и голову, а на ступенях — реальную ломаную после привязки к полу.
- Перед присоединением к старой линии и объявлением прибытия проверять опору
  и проход от текущих ног: соседний коридор за стеной не является тем же путём.
  Ошибка поиска не фиксируется для нового мира, изменившегося во время расчёта;
  изменения реальной геометрии разрешают повторную попытку без движения игрока.
- Комната и ключ сцены проверяются также перед каждым draw; старый маршрут
  не рисовать до следующего timer tick в другой комнате. Расстояние у портала
  сохраняет оставшуюся часть пути до цели. Короткий путь через портал
  не отбрасывать эвристикой прямого расстояния.
- С 1.17.1 Collider определяется по загрузке моделей, без сигнатур выпечки
  сетки НПС; навигацию самого ИИ не удалять. Старый граф не переносится на
  другой экземпляр Collider даже при том же ctx, ключе и номере revision.
- Проверки тела непрерывные: три сферы стоящего PlayerMotor, включая рёбра
  треугольников. Подъём ступени включает голову и не разрешает пересечь
  перекрытие между пробами пола. Сохранять проверку присоединения к линии.
