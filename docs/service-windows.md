Оригинал: <https://github.com/Lattymoy/daggerfall-js-source>. Публичный репозиторий
автора сейчас является снимком; проверка выполнена также на фактических JS-ассетах
релиза. Сам игровой код и файлы ARENA2 в расширение и эту документацию не включены.

Используются прежние фон, рамки и шрифты расширения. Геометрия и типографика

добавляются только при включённой русификации. Отдельной галочки установки нет.
Покупки, подтверждения, платежи, создание предметов и заклинаний выполняет оригинал.

## Расчёты и источники

`dfo_service_details.js` — только чтение и арифметика, без бросков, создания вещей,
вызова заклинания или запросов к серверу. Поддерживаемые поля берутся из родной
метаинформации эффекта, а не из приблизительной классификации по названию.

Для уровня L и соответствующего шага P:

- D = durationBase + durationMod × max(1, floor(L / max(1, P))).
- C = chanceBase + chanceMod × floor(L / max(1, P)). Вероятность 0–100%;
  у поглощения заклинаний предел 50%, используется уровень получателя.
- M = Случ[baseLow; baseHigh] + Случ[levelLow; levelHigh] × floor(L / max(1, P)).
  Два независимых целочисленных броска; показаны границы, сами броски не выполняются.

Это базовые значения. Сопротивления, школа выше 100, усиления и конкретная цель
могут менять результат. Надпись не выдаёт базовую величину за гарантированный урон.
Магический раунд — игровая минута, не фиксированное число реальных секунд.
Начальное срабатывание учитывается; срок созданного предмета равен max(0, D − 1).

Отдельно учтены передача повреждённых характеристик, запас сил ×64, ловушка душ,
рассеивание связки чар, исчезновение изгнанных существ без добычи/зачёта убийства,
стихийное сопротивление, обновление условий зачарований и ограничения прочности.
Описание «Ослабления брони» честно отражает нынешнее правило min(0, +5) в оригинале;
расширение не меняет его боевое поведение.

Числа зачарований не вычисляются по тексту названия: варианты, отфильтрованные души,
исключения и стоимость берутся через родные `primaryPickerList` / `primaryPick`.
Для CastWhen* читается действующий `spellsByIndex`, включая записи клиента,
сопоставленные с родной метаинформацией эффектов.

Исходные точки проверки: `systems/effects.js`, `systems/spellcast.js`,
`systems/absorption.js`, `systems/enchantments.js`, `systems/enchantmentCatalogue.js`,
`systems/spell/spellEffects.js`, `ui/enhanced/enhancedPorts.js`, `enhancedPort.js`,
`enhancedPicker.js`, `ui/item/itemMakerWindow.js`, `ui/spell/spellMakerWindow.js`.
Имена файлов чанков в конкретном релизе записаны в отчёте стенда.

## Производительность и отказоустойчивость

- Пять узких подключений к оригиналу; неподдержанная сигнатура оставляет модуль
  неизменённым. Повторная обработка не добавляет вторую обёртку.
- Нет новых фоновых таймеров, обхода мира или общего наблюдателя за DOM.
- Родительские окна и списки связаны через WeakMap; слушатели живут на самом списке.
- Числовое описание редактора пересчитывается при изменении параметров/уровня.
  Правая панель списка перестраивается при изменении выбранной строки или уровня.
- Ошибка нашего пояснения возвращает родной вид; сообщение пишется однократно
  для соответствующего семейства окон.

## Проверки

Финальные скриншоты и отчёт: [галерея](service-window-checks/index.html).
Скриншоты получены настоящими построителями окон опубликованного клиента,
с игровыми иконками и нашими исполняемыми преобразованиями. Данные персонажа,
товаров и сервера подставлены стендом. Это проверка клиентского интерфейса,
не совершённые покупки или банковские операции в сетевой игре.

```sh
DFO_BUILD_DIR=/path/to/verified-client \
DFO_ACORN_MODULE=/path/to/acorn \
node --test --test-isolation=none test/service-windows.test.cjs

DFO_BUILD_DIR=/path/to/verified-client \
DFO_ARENA2_DIR=/path/to/arena2 \
DFO_PLAYWRIGHT_MODULE=/path/to/playwright-core \
DFO_ACORN_MODULE=/path/to/acorn \
node tools/test-service-windows-browser.cjs
```

Стенд проверяет границы и доступность нижних кнопок на 1920×1080, 1366×768 и
1280×720; ввод и парность числовых полей, выбор мышью/клавиатурой, отмену, возврат
в родительское окно, категории торговли, заказ города и отсутствие пересчёта
описания на неизменных кадрах. Модульные проверки сравнивают D/C/M с исполняемыми
функциями опубликованного оригинала и проверяют упаковку новых файлов в ASAR.
