# Поля предметов DFO Online: полный рабочий справочник

Полный каталог **известных полей экземпляра в проверенных источниках**: 100 полей общей схемы и 15 дополнительных/совместимых. Отдельно приведены вложенные структуры, все 29 столбцов нормализованных шаблонов, связанные каталоги и вычисляемые кандидаты для будущего интерфейса.

Основа: публичный снимок оригинала `a3eb1605ea1dc391b691fe314377458a7e63e483` от 2 ноября 2026 и опубликованный релиз **0.1.14525**, проверенный 4 ноября 2026. В фактическом `starfallLaw-DZmlN_Lq.js` найден тот же набор из 100 объявленных полей: добавлений и пропусков относительно схемы снимка нет. Дополнительные поля найдены поиском записей/чтений и фабрик по 3053 JS-файлам публичного клиента. Поля частной серверной базы не объявляются доступными клиенту.

Объект предмета в игре **открытый**: неизвестные ключи могут проходить общий ограниченный перенос, а будущие обновления добавят новые. Поэтому это исчерпывающий каталог найденных известных полей данной базы, а не обещание запретить существование любых других ключей. Состав полей релиза сверён; полную совместимость всех игровых хуков этим исследованием не проверяли.

Для всех необязательных полей отсутствие, `undefined` и в валидаторе `null` — отдельное состояние, обычно «данных нет/неприменимо». Это не автоматически 0, false или «обычный предмет». Сначала проверяется форма значения, затем правила конкретного вида вещи; список допустимых чисел схемы сам по себе не доказывает законность их сочетания.

`template.*` — строка шаблона, `catalog.*` — данные связанного справочника, `derived.*` — результат расчёта/предлагаемое сводное поле, `view.*` — временная проекция. Эти префиксы введены только для объяснения таблицы и не являются новыми ключами игровой вещи. Для обычной записи корневые поля показаны без префикса.

Игровые данные и код не изменены. Приоритеты полей для карточки ещё не выбраны; генератор описаний ещё не реализован. К следующему этапу можно обращаться к полям по точным именам из этой таблицы.

В интерфейсе Enhanced дополнительно есть 9 страниц: `weapons` — Weapons, `armor` — Armor, `clothing` — Clothing, `magic` — Magic, `potions` — Potions, `ingredients` — Ingredients, `books` — Books, `valuables` — Valuables, `misc` — Misc. Это разделы отображения, а не дополнительные группы вещи.

Physical Items использует 16 своих категорий: `Weapons`, `Arrows`, `Armor`, `Clothing`, `Ingredients`, `Gold`, `Potions`, `Books`, `Gems`, `Jewellery`, `Maps`, `Magic Items`, `Religious Items`, `Quest Items`, `Transportation`, `Other Items`. Они тоже не подменяют `item.group`. Еда, руды, инструменты, ключи, альбомы, нотные листы и другие дополнения чаще определяются по шаблону внутри `UselessItems2`.

Редкость, материал, квестовость, украденность и ремесленное качество — отдельные оси, а не взаимоисключающие категории.

## Справочник материалов

Оружейные материалы: 0 — Iron, 1 — Steel, 2 — Silver, 3 — Elven, 4 — Dwarven, 5 — Mithril, 6 — Adamantium, 7 — Ebony, 8 — Orcish, 9 — Daedric.

Броня: `0=Leather`, `256=Chain`, `259=Chain2`, `512…521` — те же десять металлических ступеней. Семейство брони определяется дополнительно через RRI: стальной Mail Hauberk имеет сырой код 513, но относится к Chain. У меха возможны `material=0` и `message=1`. Материал отсутствующей записи нельзя достоверно восстанавливать через нынешний fallback `materialName`.

## Как использовать дальше

Сначала выбрать небольшой набор полей для основной карточки, затем разделить подробности и вычисляемые показатели. Для цены явно различать template.basePrice, обычную базу по материалу, сохранённую ценность экземпляра и предложение конкретного торговца. Для художественного описания использовать только подтверждённые признаки и читать уникальный авторский лор по ID. Неопознанные свойства, отсутствие материала, старые записи и фиксированные эффекты должны сохранять свои отдельные состояния.

Одинаковый набор входных данных должен давать устойчивые 2–3 предложения. Уникальная запись сможет заменять общий шаблон описания, а неизвестная будущая вещь — получать честное описание категории без выдуманных эффектов. Конкретный выбор полей и текстовые шаблоны будут отдельным следующим этапом.
