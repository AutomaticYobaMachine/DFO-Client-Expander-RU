# Диагностическая трассировка инвентаря — 1.29.7

**Задача:** зафиксировать случай, когда после перестройки инвентаря кнопки/фильтры реагируют на нажатие, но действия не выполняются, а при закрытии окно остаётся на экране, хотя игра продолжает работать.

Этот билд **не исправляет новый дефект**: он собирает факты, необходимые для локализации неисправности. Логгер не перехватывает клики, не вызывает принудительного закрытия и не меняет принципы построения окна.

## Как воспроизвести и получить журнал

1. Закрыть игру и установить диагностический EXE **1.29.7** из ветки `fix/inventory-render-reentrancy-2026-11-09`. В установщике должна быть включена опция **«Инвентарь»**.
2. Запустить игру, несколько раз открыть/закрыть рюкзак, сменить вкладку, переключить «Список/Значки», открыть контейнер и вернуться к отдельному инвентарю. Повторить привычную последовательность, при которой возникает ошибка.
3. Если окно перестало отвечать, несколько раз нажать именно неработающую кнопку/вкладку, затем попробовать закрыть окно. **Не перезапускать игру сразу:** дайте логгеру записать события. Если клавиатура всё ещё работает, можно нажать **Ctrl+Alt+Shift+F10** — это добавит маркер `trace.manual` и попросит немедленно отправить буфер; стандартные события клавиш не блокируются.
4. Завершить игру и скопировать файл **`dfo-mod-inventory-trace.ndjson`** из папки Electron `userData` для DFO Online. В типичной установке Windows это `%APPDATA%\DFO Online\dfo-mod-inventory-trace.ndjson`. При ротации потребуется и `dfo-mod-inventory-trace.previous.ndjson`. Также приложить **`dfo-mod.log`** из той же папки, записать примерное время сбоя и последовательность действий.
5. Если каталога `DFO Online` нет, найти `dfo-mod.log` в профиле игры (в старых установках встречаются `Daggerfall JavaScript` и `daggerfall-js-app`). При старте игры `dfo-mod.log` содержит строку `inventory diagnostic trace: <абсолютный путь>`.

## Что записывается

- **`overlay.claim / handoff / retire / dispose / dismiss`** — смена владельца, вызовы штатного закрытия и возврат из них, поколение оверлея;
- **`view.render.start / end / error / queued / stale / skip / reentrant`** — попытки перерисовки, исключения, грязный флаг, время построения, отложенные и устаревшие колбэки;
- **`view.remount / view.handle.unmount / view.handle.repaint`** — повторное использование DOM-хоста и жизненный цикл обработчиков;
- **`pack.head / geometry.begin / geometry.end / geometry.error`** — подготовка шапки и геометрия окна;
- **`ui.pointerdown / click / after / keydown`** — факт получения нажатия и наличие реального DOM сразу после него и через 400 мс;
- **`runtime.error / runtime.rejection`** — неперехваченные ошибки и отклонённые промисы, включая диагностический стек.

На каждом событии есть `session`, `seq`, `at` (UTC milliseconds), `received` (серверная дата), количество `.pack-shell` и `#enhanced-inventory`, состояние текущего и переданного владельца. Содержимое инвентаря и названия предметов не записываются. **Стек ошибки потенциально содержит локальные пути:** проверьте лог перед публичной публикацией.

Трассировка активна только при включённом моде и опции «Инвентарь». События отправляются внутренним `dagger://game/dfo-mod/inventory-trace` обработчиком в Electron, **не на удалённый сервер**. На стороне клиента буфер ограничен 256 событиями, POST — 12 событиями за раз, лог на диске — 4 МиБ плюс один файл предыдущей ротации. Файлы не удаляются при запуске. Если запись невозможна, сама игра продолжает работу, но часть диагностических данных может не сохраниться.

## Что искать при анализе

Сопоставить по `session` и `seq` последний успешный `view.render.end`, последующие `view.render.error`, `overlay.dispose / dismiss` и `ui.after`. Если закрытие вызвано, но `doors/shells` остаются ненулевыми спустя 400 мс — исследовать отклонённый `closeSession`, конфликт поколений и корневой хост. Если клики `ui.click` фиксируются, но ни `view.render.start`, ни `pack.*` не появляются, исследовать отключённые подписки, старый handle/owner и нативную маршрутизацию событий. Если нет `ui.click`, сначала проверить перекрытие слоёв/события указателя и жизненный цикл DOM.

**Ограничение:** трассировка фиксирует наблюдаемое поведение; синтаксические тесты и совместимость хуков с опубликованным клиентом не заменяют воспроизведение в живой игре.
